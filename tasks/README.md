# Командные задачи

Задачи ведутся чеклистами, а события по ним — в [хронологии](chronology.md). Имена участников пока обозначены ролями: Разработчик 1–3.

Новые задания по итогам исследований формулирует пользователь. После этого заносить их в чеклист нужного разработчика и добавлять отдельную датированную запись в хронологию; не придумывать следующие задания заранее.

| Разработчик | Задача | Состояние |
|---|---|---|
| 1 | [Анализ данных](01-data-analysis.md) | Не начата |
| 2 | [Стратегия пилотов](02-pilot-strategy.md) | Не начата |
| 3 | [Агент и интеграция](03-agent-implementation.md) | В работе: каркас создан |

## Работа команды

- [ ] Разработчики 1 и 2 анализируют данные и стратегию параллельно.
- [ ] Разработчик 3 владеет `agent.py`, сначала готовит каркас, затем интегрирует результаты 1 и 2.
- [ ] Передать выводы Разработчиков 1 и 2 Разработчику 3 до финальной настройки агента.
- [ ] Перед параллельной правкой назначить одного владельца для каждого файла.

Базовый стек: Python, pandas (уже используется в шаблоне) и стандартная библиотека. Пилотный резерв 15–20% бюджета — только стартовая гипотеза, её следует обосновать данными и стоимостью каналов. Ограничения кейса и интерфейс среды указаны в `context/PARTICIPANT_GUIDE.md`. Данные синтетические; мок-эффекты не являются прогнозом судейства.
