# Задача 1 — анализ данных

**Исполнитель:** Разработчик 1  
**Владелец результата:** Разработчик 1  
**Состояние:** Не начата  
**Зависимости:** нет

## Цель

Выделить по предоставленной истории и профилю аудитории кандидатов для проверки пилотами. Исторические эффекты — ориентир для ранжирования, а не гарантированный прогноз целевой выборки.

## Чеклист

- [ ] Прочитать `context/PARTICIPANT_GUIDE.md`, `context/feature_dictionary.csv` и `context/tariff_dictionary.csv`.
- [ ] Изучить `context/data/change_tariff.csv` и `context/customer_profile.csv`; при необходимости посмотреть историю трафика и месячного ARPU.
- [ ] Проверить поля, пропуски, масштабы и покрытие тарифов/сегментов.
- [ ] Найти переходы с признаками роста/падения ARPU и, где данные позволяют, сравнить их по текущему тарифу, ARPU-сегменту и поведению.
- [ ] Сопоставить исторические наблюдения с размером сегментов текущей аудитории.
- [ ] Передать команде краткую записку с ключевыми колонками и ограничениями данных.
- [ ] Включить несколько кандидатов «текущий тариф → целевой тариф → сегмент», размер аудитории и степень уверенности/нехватки данных.

## Критерий готовности

Другой разработчик может использовать записку для списка пилотов и видит, какие выводы основаны на истории, а какие являются гипотезами. Не редактировать `agent.py` без отдельного согласования с Разработчиком 3.
